# v0.14.2: Linux NIC And Interface Evidence

Date: 2026-08-08

## Why This Release Exists

Network troubleshooting starts at the interface.

Before blaming DNS, Kubernetes, firewalls, load balancers, or the application,
an operator needs to know whether the NIC itself is healthy:

```text
interface inventory
  -> link state
  -> carrier
  -> speed and duplex
  -> RX/TX errors and drops
  -> driver and firmware
  -> driver counters
```

This release preserves that Linux-first troubleshooting habit as a native AOP
command.

## What Changed

New CLI path:

```bash
aop linux nic
aop linux nic --iface ens5
aop linux nic --iface ens5 --json
```

New evidence sources:

- `ip -br link`
- `ip -br address`
- `ip -s link`
- `ip -s link show dev <IFACE>`
- `/sys/class/net/<IFACE>/operstate`
- `/sys/class/net/<IFACE>/carrier`
- `/sys/class/net/<IFACE>/speed`
- `/sys/class/net/<IFACE>/duplex`
- `ethtool <IFACE>`
- `ethtool -i <IFACE>`
- `ethtool -S <IFACE>`

## Operator Interpretation

This command helps an SRE quickly identify:

- link down
- no carrier
- speed or duplex mismatch
- RX/TX drops
- RX/TX errors
- driver or firmware visibility
- driver-specific queue, reset, or discard counters
- missing utilities such as `ethtool`
- missing permission or unsupported interface evidence

## Safety Boundary

NIC collection is read-only.

It does not:

- bring interfaces up or down
- change routes
- alter MTU
- change offload settings
- reset drivers
- capture packets
- change firewall state

## What Remains Next

The next network step is deterministic investigation:

```bash
aop investigate linux network --iface ens5
```

That future workflow should classify link-down, no-carrier, error/drop
pressure, route problems, DNS failures, listener problems, and Kubernetes CNI
correlation.

# v0.12.0: Linux Disk Incident Intelligence

Date: 2026-06-10

## Why This Release Exists

This release moved AOP beyond raw Linux command collection into deterministic
Linux disk diagnosis.

The product idea is important:

```text
Disk symptom
  -> collect bounded read-only evidence
  -> parse facts
  -> classify the likely disk incident
  -> explain severity and confidence
  -> preserve incident memory
```

AOP should not say "disk full" only because one command produced high usage.
It should separate byte exhaustion, inode exhaustion, deleted-open files,
rapid growth, read-only filesystems, kernel storage errors, and missing
evidence.

## What Was Added

- `aop investigate linux disk`
- deterministic Linux disk agent
- Linux disk workflow orchestration
- typed disk investigation and finding contracts
- Linux-native incident memory persistence
- semantic indexing attempt with structured-memory fallback
- tests for disk classification, CLI behavior, workflow, and persistence

## Important Commands

```bash
aop linux disk --path /var
aop investigate linux disk --path /var
aop investigate linux disk --path /var --format json
aop investigate linux disk --path /var --no-persist
```

## Troubleshooting Logic Captured

The disk agent reasons over evidence for:

- filesystem byte capacity
- inode pressure
- mount source, type, and options
- read-only filesystem state
- bounded directory growth
- recently changed large files
- deleted files still held open by processes
- kernel filesystem and storage errors
- evidence gaps when the host cannot provide enough facts


Raw collection remains available through `aop linux disk`. Interpretation and
memory happen through `aop investigate linux disk`.

## Boundaries

- No LLM is required for the disk diagnosis.
- No delete, truncate, restart, unmount, repair, or resize action is executed.
- Live Linux validation on real ext4, XFS, LVM, container, NFS, and cloud
  examples is still needed.
- General Linux RCA beyond the disk domain remains future work.

## Why It Matters For The Larger AOP Goal

This release proves the pattern AOP should repeat across Linux domains:

```text
safe evidence
  -> deterministic interpretation
  -> confidence and evidence gaps
  -> next read-only check
  -> memory
```

That pattern is the base for future CPU, memory, process, network, systemd,
kernel, Kubernetes-node, and AWS troubleshooting intelligence.

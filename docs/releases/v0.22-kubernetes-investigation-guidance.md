# v0.22.0: Kubernetes Investigation Guidance Integration

Date: 2026-08-08

## Purpose

v0.22 connects the v0.20 Kubernetes-to-Linux correlation catalog and the v0.21
Kubernetes issue knowledge catalog into the real Kubernetes investigation
workflow.

Before this release, the knowledge existed behind separate commands:

```bash
aop investigate k8s-linux --incident OOMKilled
aop investigate k8s-knowledge --symptom OOMKilled
```

Now the normal investigation path can carry that guidance:

```bash
aop investigate k8s -n ai-lab
```

## Added

- `IncidentKnowledgeGuidance` workflow schema
- `correlation_guidance` on `WorkflowExecutionResponse`
- workflow enrichment that maps classified Kubernetes symptoms to:
  - curated Kubernetes issue knowledge
  - Linux evidence requirements
  - safe next `aop linux` commands
  - do-not-assume rules
  - evidence gaps when no catalog entry exists
- terminal summary guidance
- JSON report guidance
- Markdown report guidance
- tests for workflow enrichment and CLI report rendering

## Boundary

This release does not SSH to nodes, run Linux commands remotely, or collect
live host evidence from Kubernetes nodes. It tells the SRE what evidence is
needed and which safe AOP command should collect it.

## Next

The next step is to prepare dashboard/evidence timeline views that can display
Kubernetes incidents, Linux evidence requirements, deterministic findings, and
memory side by side.

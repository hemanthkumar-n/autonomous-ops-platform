# v0.28.0: Kubernetes Node To Linux Correlation

Date: 2026-08-14

## Why This Release Exists

Kubernetes node conditions are orchestration signals, not final root cause.

`DiskPressure`, `MemoryPressure`, `PIDPressure`, `NetworkUnavailable`, and
`Ready=False` all require Linux host evidence before an SRE decides what to do.

v0.28 adds a deterministic node-to-Linux planner:

```bash
aop investigate k8s-node --node worker-01 --condition DiskPressure
```

## What It Does

The planner maps Kubernetes node symptoms to the Linux evidence path:

- `DiskPressure` -> kubelet path, runtime path, filesystem, inode, LVM,
  multipath, NFS, and I/O checks
- `MemoryPressure` -> host memory, swap, PSI, OOM, and cgroup checks
- `PIDPressure` -> process count, process tree, PID cgroups, kubelet/runtime
  impact
- `NetworkUnavailable` -> NIC, carrier, routes, DNS, CNI, and cloud network
  evidence
- `ReadyFalse` / `NodeNotReady` -> kubelet, runtime, network, storage,
  memory, CPU, kernel, and cloud instance health

## User-Facing Commands

```bash
aop investigate k8s-node --node worker-01
aop investigate k8s-node --node worker-01 --condition DiskPressure
aop investigate k8s-node --node worker-01 --condition DiskPressure --condition ReadyFalse
aop investigate k8s-node --node worker-01 --condition NetworkUnavailable --format json
aop investigate k8s-node --node worker-01 --list-conditions
```

## Safety Boundary

This release is planning only.

It does not:

- SSH into nodes
- drain nodes
- restart kubelet or container runtime
- delete images or files
- modify Kubernetes objects
- modify Linux networking, filesystems, cgroups, or services
- execute remediation

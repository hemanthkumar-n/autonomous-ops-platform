# v0.14.0: Linux Complex Scenario Plans

Date: 2026-08-08

## Why This Release Exists

v0.14 starts turning senior Linux troubleshooting experience into reusable AOP
workflow memory.

The goal is not to run a huge command list. The goal is to preserve the order
an experienced Linux administrator uses when the symptom is confusing:

```text
symptom
  -> likely causes
  -> first safe checks
  -> interpretation
  -> common traps
  -> Kubernetes, AWS, and cgroup correlation
```

This keeps AOP useful for real SRE work where the hardest question is often:

```text
Where do I start, and what should I not assume?
```

## What Changed

New CLI path:

```bash
aop linux plan scenario --list
aop linux plan scenario high-load
aop linux plan scenario oom --json
```

New implementation:

```text
app/tools/troubleshooting/linux_scenarios.py
```

New behavior:

- lists complex Linux troubleshooting scenarios
- renders one selected scenario in human-readable form
- supports JSON output for future UI and agents
- accepts common aliases such as `oom`, `fdisk`, `diskpressure`, `listener`,
  and `d-state`
- keeps the workflow read-only and advisory

## Implemented Scenario Plans

- high load with low CPU usage
- memory pressure and OOM evidence
- `df` and `du` mismatch
- inode exhaustion
- read-only filesystem remount
- file descriptor exhaustion
- port conflict or missing listener
- systemd restart loop
- kernel panic or previous boot crash
- LVM, partition, and filesystem expansion mismatch
- container runtime disk pressure

## Demo Commands

```bash
aop linux plan scenario --list
aop linux plan scenario high-load
aop linux plan scenario memory-pressure
aop linux plan scenario oom --json
aop linux plan scenario diskpressure
```

Example operator flow:

```text
High load but CPU is not busy
  -> aop linux plan scenario high-load
  -> inspect load, process state, D-state tasks, vmstat, iostat, PSI, and
     kernel logs
  -> correlate with Kubernetes node pressure or AWS/EBS latency when relevant
```

## Safety Boundary

`aop linux plan scenario` does not execute commands. It teaches and plans the
investigation path.

This release does not add automatic Linux cross-signal diagnosis beyond the
existing disk investigation workflow. It also does not add remediation,
service restarts, deletes, filesystem repairs, mount changes, or cloud changes.

## Relationship To Existing Memory

The human-authored scenario memory remains preserved at:

```text
app/memory/knowledgebase/linux_complex_troubleshooting_scenarios.md
```

The new code catalog makes that knowledge executable as a CLI planning surface
without forcing the runtime to parse Markdown.

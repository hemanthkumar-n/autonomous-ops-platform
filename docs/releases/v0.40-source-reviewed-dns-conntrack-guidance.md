# v0.40.0: Source-Reviewed DNS And Conntrack Guidance

Date: 2026-08-14

## Why

v0.39 imported 59 Kubernetes failure-story records as metadata. v0.40 proves
the review path from historical discovery to bounded reusable guidance.

## Reviewed Sources

The first source-backed reviews cover:

- Zalando's 2019 total Kubernetes DNS outage involving retries, CoreDNS memory,
  OOM kills, ndots behavior, and monitoring blast radius.
- loveholidays' 2020 conntrack exhaustion incident involving GKE node sizing,
  connection fan-out, resets, timeouts, and conntrack capacity.

The inaccessible Medium source remains metadata-only. AOP does not infer facts
from an article it could not review.

## Knowledge Separation

Each review records:

```text
reported symptoms
reported root cause
contributing factors
reported mitigation
reusable checks
safe read-only commands
risky or historical actions
version/cloud applicability
```

Only reusable checks and safe commands become RAG guidance.

## Commands

```bash
aop runbooks review queue
aop runbooks review search --text "DNS CoreDNS OOM"
aop runbooks review show review-k8s-dns-coredns-oom-zalando-2019
aop runbooks review show review-k8s-linux-conntrack-loveholidays-2020

aop runbooks search \
  --domain kubernetes.networking \
  --incident-type DNSFailure \
  --text "CoreDNS OOM ndots retries monitoring" \
  --format prompt
```

## Safety Boundary

- The historical CoreDNS `2000Mi` recovery value is not reusable guidance.
- Historical conntrack sysctl values are not reusable guidance.
- Privileged init-container or DaemonSet mutation examples never enter safe
  command output.
- Current Kubernetes version, managed-service defaults, CNI, kube-proxy mode,
  cloud provider, kernel, and workload evidence must be checked.

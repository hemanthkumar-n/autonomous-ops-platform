# v0.18.0: Linux systemd Service Investigation

Date: 2026-08-08

## Why This Release Exists

Restarting a failed service is not troubleshooting.

This release preserves the correct systemd investigation order:

```text
unit state
  -> result
  -> exit status
  -> restart policy
  -> unit file and drop-ins
  -> recent journal errors
```

## What Changed

New CLI path:

```bash
aop investigate linux service --service nginx
aop investigate linux service --service nginx.service --format json
```

New deterministic findings:

- `start_limit_hit`
- `service_failed`
- `nonzero_exit_status`
- `restart_policy_loop`
- `journal_error_evidence`
- `insufficient_evidence`

## Safety Boundary

The service investigator is read-only.

It does not:

- restart services
- reload services
- enable or disable units
- reset failed state
- mask or unmask units
- edit unit files
- kill service processes

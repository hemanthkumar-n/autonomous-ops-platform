# AOP v0.43 - Multi-Collector Autonomous Investigation

## Goal

Extend the bounded autonomous investigation loop from Linux memory into CPU, disk/storage, and network evidence while preserving the same read-only collector boundary, deterministic hypothesis updates, RCA gating, resource identity, and no-remediation policy.

v0.43 is an evidence-acquisition milestone. It does **not** expand autonomous remediation.

## Added

- `linux_cpu`, `linux_disk`, and `linux_network` autonomous collector adapters
- shared Linux investigation normalization into `EvidenceCollectionResult`
- default Linux collector registry containing memory, CPU, disk, and network collectors
- scope forwarding for disk `path` and network `iface`
- host/node/resource metadata propagation through planner requests
- source workflow confidence, findings, and evidence-gap metadata in normalized evidence
- planner validation across CPU, disk, and network gap requests
- deterministic multi-collector demo that investigates one case across three host domains
- macOS-safe dependency-injected tests for all new adapters
- current development-state documentation in `docs/CURRENT_STATUS.md`

## Architecture

```text
InvestigationCase
      |
      v
EvidencePlanner
      |
      +--> linux_memory  -> existing memory workflow
      +--> linux_cpu     -> existing CPU workflow
      +--> linux_disk    -> existing disk workflow
      +--> linux_network -> existing network workflow
      |
      v
EvidenceCollectionResult
      |
      +--> normalized EvidenceItem(s)
      +--> resource identity
      +--> hypothesis support / why / why-not
      +--> resolved RCA-blocking gaps
      |
      v
Confidence re-evaluation
      |
      +--> collect more evidence
      +--> RCA candidate
      +--> safe stop boundary
```

Several gaps can be planned and collected for one canonical case. The collectors do not become independent incident engines; their evidence converges back into the same `InvestigationCase` before the confidence decision is recalculated.

## RCA Contract

v0.43 preserves the v0.42 distinction:

```text
rca_candidate != confirmed root_cause
```

An RCA candidate contains the leading hypothesis, confidence, supporting and contradicting evidence, and `why` / `why_not` reasoning. `root_cause` remains unconfirmed until a later controlled validation/confirmation path explicitly promotes it.

## Safety

- No arbitrary shell execution is added.
- Every collector calls an existing AOP read-only workflow.
- Autonomous collection forces `persist=False` so evidence acquisition does not create incident-memory side effects.
- Only explicitly registered collector names can execute.
- Step/request budgets remain bounded.
- No restart, cleanup, route change, filesystem mutation, NIC mutation, Kubernetes mutation, or remediation action is introduced.
- Missing or insufficient domain evidence does not resolve the associated RCA-blocking gap.
- Collector failure must result in an audited safe stop/continuation decision rather than fabricated evidence.

## Next

The next useful expansion is Kubernetes and Prometheus read-only collectors. Those should reuse the same request/result contract and should not expose arbitrary `kubectl` or free-form PromQL execution to the planner.

The next target investigation is cross-domain:

```text
Kubernetes symptom
      -> Kubernetes evidence
      -> workload/node identity
      -> Linux evidence
      -> bounded Prometheus history
      -> competing hypotheses
      -> confidence + why / why-not
      -> RCA candidate or collect more evidence
```

Remediation remains deliberately outside this milestone.

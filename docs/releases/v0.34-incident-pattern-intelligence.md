# v0.34.0: Incident Pattern Intelligence

## Purpose

v0.34.0 starts the first real Incident Pattern Intelligence implementation.
The goal is to help AOP answer a practical SRE question:

```text
Have we seen this before?
```

This first slice is deterministic. It does not call an LLM and does not use
semantic similarity. It reads structured local memory, builds stable
fingerprints, groups recurring occurrences, and exposes them through the CLI.

## What Changed

- Added deterministic Kubernetes pattern fingerprints.
- Added deterministic Linux pattern fingerprints.
- Added pattern occurrence and pattern report schemas.
- Added structured-memory pattern loading for:
  - `incident_memory_*.json`
  - `linux_*_*.json`
- Added `aop memory patterns`.
- Added pattern tests and CLI tests.

## Demo

```bash
aop memory patterns --min-count 2
aop memory patterns --domain linux.disk --format json
```

## Current Boundary

This is recurrence lookup, not proof of root cause.

AOP must still:

- collect current evidence
- identify missing evidence
- respect deterministic contradictions
- treat historical similarity as a clue
- avoid automatic remediation

## Why It Matters

This is the first step toward pattern-aware RCA:

```text
current incident
  -> deterministic finding
  -> memory fingerprint
  -> previous occurrences
  -> pattern-aware investigation hint
  -> bounded RCA context
```

Future releases should connect these pattern summaries into Kubernetes and
Linux investigation output, Markdown reports, and eventually AI prompts.

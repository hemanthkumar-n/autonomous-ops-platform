# v0.41.0: Unified Operational Knowledge Retrieval

Date: 2026-08-14

## Why This Release Exists

AOP had useful knowledge in separate paths: curated runbooks, reviewed public
incidents, exact incident history, semantic memory, and recurrence patterns.
Agents should not need to understand every storage implementation to retrieve
safe operational context.

v0.41 introduces one typed, bounded, provenance-bearing retrieval interface.

## Retrieval Flow

```text
KnowledgeQuery + live evidence references
  -> curated internal runbooks
  -> source-reviewed external guidance
  -> exact structured incident memory
  -> recurring incident patterns
  -> optional semantic incident similarity
  -> normalized ranking and provenance
  -> bounded CLI, JSON, or RCA prompt context
```

## Operator Commands

```bash
aop knowledge search \
  --domain kubernetes.networking \
  --incident-type DNSFailure \
  --text "CoreDNS OOM retries ndots"

aop knowledge search \
  --domain linux.disk \
  --text "df du deleted open inode" \
  --format prompt

aop knowledge search --text "OOMKilled cgroup" --semantic --format json
```

Semantic retrieval is opt-in. The default path does not require Ollama,
embeddings, Chroma, Kubernetes, or network access.

## Trust And Provenance

Every normalized match identifies a source type and trust level:

| Source type | Trust label | Meaning |
|---|---|---|
| `internal_runbook` | `curated` | Source-controlled AOP guidance |
| `reviewed_external` | `source_reviewed` | Guidance extracted through AOP source review |
| `incident_memory_exact` | `historical_evidence` | Exact structured local incident match |
| `incident_pattern` | `historical_recurrence` | Repeated local incident fingerprint |
| `incident_memory_semantic` | `historical_similarity` | Optional similarity clue |

These labels prevent a similar old incident from being presented as a verified
root cause for the active incident.

## Agent Integration

The Kubernetes RCA agent now receives one bounded knowledge context instead of
assembling runbook and historical-memory prompt sections independently. Live
evidence references are carried into that context, and pattern guidance from
the active workflow remains separately visible for exact case correlation.

## Safety Boundary

This release retrieves and formats knowledge. It does not SSH, drain nodes,
restart services, delete resources, modify sysctls, or mutate Linux or
Kubernetes state. Commands are advisory and must be validated against current
evidence.

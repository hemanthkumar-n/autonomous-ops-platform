# v0.35.0: Pattern-Aware Investigation Output

## Purpose

v0.35.0 connects Incident Pattern Intelligence to the Kubernetes investigation
workflow. v0.34 could find recurring patterns through `aop memory patterns`;
v0.35 starts using that memory while investigating active incidents.

## What Changed

- Added `IncidentPatternGuidance` to workflow responses.
- Added exact historical pattern lookup for active Kubernetes incidents.
- Added pattern memory output to `aop investigate k8s` summary.
- Added pattern memory output to Markdown incident reports.
- Added `pattern_guidance` to JSON investigation output.
- Added tests for workflow wiring, CLI rendering, and active-incident pattern
  lookup.

## Example Output Direction

```text
Pattern memory:
- fingerprint: kubernetes:payments:checkout:memoryexhaustion:oomkilled
- recurrence: 2 previous occurrence(s)
- latest: 2026-08-14T00:00:00+00:00
- boundary: Historical recurrence is a clue, not proof of root cause.
```

## Boundary

This release does not send pattern memory to an LLM yet. It does not claim
root cause from history alone. It does not mutate infrastructure.

The current behavior is exact deterministic recurrence guidance only.

## Next

The next step is to use bounded pattern summaries in RCA prompt context and to
add similar recurrence hints to Linux investigation summaries.

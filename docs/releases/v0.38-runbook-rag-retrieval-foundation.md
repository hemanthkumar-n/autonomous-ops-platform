# v0.38.0: Runbook RAG Retrieval Foundation

Date: 2026-08-14

## Why

AOP already had structured incident memory and pattern recurrence. The next
step was to let investigations consult trusted runbook knowledge without
turning the prompt into a raw document dump.

v0.38 starts that foundation.

## What Changed

- Added source-controlled runbook chunks.
- Added deterministic runbook retrieval by domain, incident type, and text.
- Added bounded runbook context formatting for prompts.
- Added `aop runbooks list`.
- Added `aop runbooks search`.
- Added Kubernetes RCA prompt integration through `Bounded Runbook/RAG Context`.

## Demo

```bash
aop runbooks list
aop runbooks search --domain kubernetes --incident-type MemoryExhaustion --text "OOMKilled cgroup memory limit"
aop runbooks search --domain linux.memory --incident-type OOMKilled --text "memory.events psi oom_kill" --format prompt
```

## Current Runbook Coverage

The initial trusted chunks cover:

- Kubernetes OOMKilled with Linux memory/cgroup correlation
- ImagePullBackOff with registry, DNS, and node network checks
- Kubernetes DiskPressure with Linux storage investigation
- Linux disk full and df/du mismatch
- Linux cgroup memory pressure and container limits

## Safety Boundary

This is retrieval only. It does not:

- SSH to servers
- mutate Kubernetes
- delete files
- restart services
- repair filesystems
- drain nodes
- execute remediation

Runbook matches are guidance, not proof. AOP must still verify every claim
against current live evidence.

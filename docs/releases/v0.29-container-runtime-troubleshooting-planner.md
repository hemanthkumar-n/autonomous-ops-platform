# v0.29.0: Container Runtime Troubleshooting Planner

Date: 2026-08-14

## Why This Release Exists

Kubernetes symptoms often land at the runtime layer:

- `ImagePullBackOff`
- `ErrImagePull`
- `CreateContainerError`
- `DiskPressure`
- `PIDPressure`
- `NetworkUnavailable`
- `NodeNotReady`

The runtime layer is dangerous to touch blindly. Restarting kubelet or
containerd, pruning images, or deleting runtime directories can change the
incident, disrupt pods, and destroy useful evidence.

v0.29 adds a planner that trains AOP and SREs on what to inspect before taking
live action.

## User-Facing Commands

```bash
aop investigate linux runtime
aop investigate linux runtime --runtime containerd --symptom image-pull
aop investigate linux runtime --runtime crio --symptom disk-pressure
aop investigate linux runtime --runtime docker --symptom runtime-down
aop investigate linux runtime --runtime containerd --symptom cgroup --format json
aop investigate linux runtime --list
```

## What The Plan Covers

- runtime service state
- kubelet service relation
- runtime and kubelet journals
- runtime storage paths
- pod log paths
- runtime image/container inventory
- image pull, registry, DNS, proxy, certificate, and auth clues
- container creation, mount, SELinux, overlay, and cgroup setup clues
- CNI configuration and sandbox networking clues
- PID pressure and TasksMax clues
- cgroup v1/v2 and memory/cgroup event clues
- Kubernetes symptom correlation
- AWS/cloud correlation
- dangerous actions to avoid first

## Dangerous Actions Marked Explicitly

- `systemctl restart containerd`
- `systemctl restart crio`
- `systemctl restart docker`
- `systemctl restart kubelet`
- `rm -rf /var/lib/containerd`
- `rm -rf /var/lib/containers`
- `rm -rf /var/lib/docker`
- `crictl rmi --prune`
- `docker system prune`

## Safety Boundary

This release is planner/read-only.

It does not:

- restart kubelet
- restart containerd, CRI-O, or Docker
- prune images
- delete runtime data
- modify CNI
- alter cgroups
- change Kubernetes objects
- execute remediation

Live execution is intentionally delayed until real Linux/Kubernetes server
trials.

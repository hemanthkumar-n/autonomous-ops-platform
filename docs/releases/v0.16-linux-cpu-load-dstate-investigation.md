# v0.16.0: Linux CPU, Load, And D-State Investigation

Date: 2026-08-08

## Why This Release Exists

High load is not the same as high CPU.

Experienced Linux troubleshooting starts by separating:

```text
runnable CPU demand
blocked D-state tasks
I/O wait
CPU pressure stall
hypervisor steal time
missing evidence
```

This release turns that Linux-first reasoning into a deterministic AOP
investigation workflow.

## What Changed

New CLI path:

```bash
aop investigate linux cpu
aop investigate linux cpu --top 20
aop investigate linux cpu --format json
```

New implementation:

```text
app/agents/linux/cpu_agent.py
app/orchestration/linux_cpu_workflow.py
```

New deterministic findings:

- `d_state_blocked_tasks`
- `io_pressure_behind_load`
- `cpu_saturation`
- `steal_time_pressure`
- `high_load_low_cpu`
- `insufficient_evidence`

## Operator Interpretation

AOP now preserves the important operational distinction:

- high load plus `D` state points toward kernel-blocked work
- high load plus I/O wait or I/O PSI points toward storage or lower-layer wait
- high user/system CPU or CPU PSI points toward runnable CPU contention
- steal time points toward virtualization or cloud host scheduling pressure
- low CPU with high load requires task-state and wait analysis before tuning

## Safety Boundary

The CPU investigator is read-only.

It does not:

- kill processes
- renice processes
- restart services
- tune kernel parameters
- alter cgroup limits
- change cloud instance capacity

## What Remains Next

The next Linux expansion should turn NIC/network evidence into deterministic
network investigation:

```bash
aop investigate linux network --iface ens5
```

That should classify link down, no carrier, error/drop pressure, route issues,
DNS failures, and listener problems.

# v0.19.0: Linux Investigation Ladder And Release Memory

Date: 2026-08-08

## Purpose

v0.19 is a consolidation release. It makes the Linux troubleshooting progress
visible as a coherent investigation ladder instead of a fast sequence of
individual feature commits.

This matters because AOP is intended to preserve experienced Linux
administration judgment, not only expose commands.

## What Changed

- Added `docs/linux/LINUX_INVESTIGATION_LADDER.md`
- Updated README release memory and current version to `v0.19.0`
- Updated roadmap language so v0.14 through v0.18 read as completed history
- Updated handover and setup docs with the current baseline
- Kept the regression baseline at 115 offline tests

## Investigation Ladder

The documented Linux path is:

```text
health
  -> explain
  -> plan
  -> collect domain evidence
  -> investigate deterministically
  -> persist memory
  -> correlate to Kubernetes, AWS, dashboards, and approvals
```

The ladder covers:

- disk and filesystem investigation
- memory and OOM investigation
- CPU, load, I/O wait, steal time, and D-state investigation
- NIC and network investigation
- systemd service investigation
- Linux internals and cgroup evidence

## Demo

```bash
aop --version
aop linux health
aop linux plan scenario high-load
aop investigate linux disk --path /var
aop investigate linux memory --pid 4242
aop investigate linux cpu
aop investigate linux network --iface ens5
aop investigate linux service --service nginx
```

## Boundary

This release does not add a new collector or investigator. It documents and
stabilizes the Linux mental model so future code changes have a clear place in
the product story.

## Next

The next meaningful step is to correlate domains:

- Kubernetes pod and node symptoms to Linux host evidence
- AWS logs and change events to Linux and Kubernetes evidence
- dashboard-ready summaries from existing typed evidence contracts
- AI RCA grounded in deterministic Linux evidence

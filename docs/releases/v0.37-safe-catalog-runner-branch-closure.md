# v0.37.0: Safe Catalog Runner And Branch Closure

Date: 2026-08-14

## Why

Two old remote branches were still visible:

```text
origin/feature/aop-cli-transition
origin/feature/investigation-core-v022
```

Both branches were older than current `main`. A direct merge would have
removed large parts of the modern Linux, Kubernetes, incident memory, and
release-note work. The right move was to inspect them, keep useful ideas, and
close them without regressing the platform.

## What Changed

- Added `aop catalog` for command catalog visibility.
- Added a safe troubleshooting catalog executor.
- Added command lookup and search helpers for the catalog.
- Added tests for catalog listing, placeholder skipping, careful-read skipping,
  and shell-free execution.

## Branch Outcome

`origin/feature/investigation-core-v022`:

- The useful investigation-core work is already present in current `main`.
- Current `main` has the canonical `InvestigationCase`, confidence engine,
  reasoning summaries, adapters, and tests.

`origin/feature/aop-cli-transition`:

- The branch is superseded by the current AOP CLI, Linux investigations, LLM
  routing, token policy, and release history.
- Its useful guarded-runner idea was ported into the current troubleshooting
  catalog architecture.

## Demo

```bash
aop catalog list --domain linux
aop catalog search memory
aop catalog run linux_cpu_load --json
aop catalog run k8s_node_describe --json
```

The last command is intentionally skipped because it contains placeholders.
AOP should not guess a live node name.

## Safety Boundary

The catalog runner is opt-in and read-only. It does not SSH, drain nodes,
restart services, delete files, change kernels, mutate Kubernetes objects, or
repair filesystems.

Commands are skipped when they:

- require placeholder values such as `<node>` or `<namespace>`
- require root without explicit elevated-read allowance
- are marked as careful production scans without explicit careful-read
  allowance

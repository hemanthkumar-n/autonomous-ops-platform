# v0.13.0: Linux Explain and Disk Planning

Date: 2026-08-07

## Why This Release Exists

This release starts turning AOP into a teaching troubleshooting system, not
only a command runner.

The founder direction is:

```text
Do not just run commands.
Explain why the command matters.
Explain what each argument contributes.
Plan the investigation before collecting evidence.
Preserve experienced Linux admin reasoning for future SREs.
```

That is the beginning of AOP's unique value: an SRE tool that combines Linux,
Kubernetes, AWS, operational memory, and AI reasoning without losing the
ground reality of production troubleshooting.

## What Was Added

- `aop linux explain <command>`
- `aop linux plan disk --path <path>`
- Linux command explanation lookup from the argument reasoning catalog
- placeholder-aware matching for real command examples
- read-only disk investigation plan with Kubernetes and AWS/EBS correlation
- JSON output for command explanations and disk plans
- tests for explain and plan CLI behavior
- observability, dashboard, alert-signal, and future provider strategy
  documented for upcoming architecture work

## Explain Workflow

`aop linux explain` returns:

- command purpose
- argument meaning
- troubleshooting value
- risk level
- whether elevated read access may be required
- incident types where the command is useful
- AOP guidance
- related next commands

It does not execute the command.

Example:

```bash
aop linux explain "lsof -p 4242"
```

This explains why `-p <pid>` targets one process and why the command is useful
for file descriptor, socket, deleted-file, and process investigation.

## Plan Workflow

`aop linux plan disk --path /var` prints the disk troubleshooting order before
any collector runs:

```text
filesystem bytes and type
  -> inode usage
  -> mount identity and options
  -> bounded directory growth
  -> recent large files
  -> deleted-open files
  -> kernel filesystem and storage errors
  -> I/O latency
  -> Kubernetes node correlation
  -> AWS/EBS correlation
```

The plan command does not require the path to exist locally. That allows an
operator to prepare an investigation for a remote server, Kubernetes node, or
company-specific application path before logging into the target host.

## Boundaries

- `aop linux explain` does not execute commands.
- `aop linux plan` does not collect evidence.
- AI RCA for general Linux incidents is not implemented yet.
- Kimi/Moonshot provider runtime support is planned but not implemented yet.
- AOP dashboard and graphing contracts are planned but not implemented yet.
- The next step is to connect disk findings with command explanations.

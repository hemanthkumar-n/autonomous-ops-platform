# v0.20.0: Kubernetes To Linux Correlation Training

Date: 2026-08-08

## Purpose

v0.20 teaches AOP how common Kubernetes symptoms map to Linux evidence.

This is the first cross-domain correlation foundation after the Linux ladder.
It keeps AOP honest: Kubernetes can report the orchestration symptom, but the
root cause may live in Linux memory, cgroups, filesystems, NICs, services,
container runtime state, or cloud infrastructure.

## Covered Kubernetes Symptoms

- `OOMKilled`
- `CrashLoopBackOff`
- `ImagePullBackOff`
- `ErrImagePull`
- `CreateContainerConfigError`
- `CreateContainerError`
- `FailedScheduling`
- `DiskPressure`
- `MemoryPressure`
- `NodeNotReady`

## Example

```bash
aop investigate k8s-linux --incident OOMKilled
```

Expected meaning:

```text
Kubernetes reports the container was killed for memory.
AOP asks for Linux memory, cgroup, PSI, VM, and kernel OOM evidence.
AOP does not assume host memory is exhausted.
```

## Boundary

This release does not collect live Linux node evidence from Kubernetes nodes.
It creates the safe planning layer for that future work.

Node-pressure simulations such as `DiskPressure`, `MemoryPressure`, and
`NodeNotReady` are intentionally not forced by default manifests because they
can harm a shared cluster. They are covered by the correlation catalog and
should be reproduced only in isolated labs.

## Next

# v0.25.0: Linux Boot, Kernel, And grubby Investigation

Date: 2026-08-14

## Purpose

v0.25 converts the boot/kernel/grubby shortcut knowledge into a deterministic
Linux investigation workflow.

This is the first deeper Linux investigator after the `aop lx` shortcut layer.

## Added

- `aop investigate linux boot`
- JSON output through `aop investigate linux boot --format json`
- read-only boot/kernel evidence collection:
  - running kernel
  - kernel identity
  - `/proc/cmdline`
  - systemd boot history
  - recent reboot history
  - boot health
  - boot performance
  - current kernel warnings/errors
  - previous-boot warnings/errors
  - kdump status
  - grubby default kernel
  - grubby default index
  - grubby boot entry inventory
- deterministic findings for:
  - previous boot panic/oops
  - current kernel panic/oops
  - kernel OOM evidence
  - hung task or blocked kernel waits
  - storage/filesystem kernel errors
  - kdump unavailable
  - running/default kernel mismatch
  - risky boot arguments
  - insufficient evidence
- structured Linux boot/kernel incident persistence
- tests for agent parsing, workflow persistence, collector safety, and CLI
  output

## Safety

This release does not change bootloader state, set a default kernel, update
kernel arguments, regenerate GRUB config, reboot, trigger sysrq, unload
drivers, or tune kernel parameters.

Commands such as `grubby --set-default`, `grubby --update-kernel`, `reboot`,
and `echo c > /proc/sysrq-trigger` remain human-controlled actions outside
this workflow.

## Example

```bash
aop investigate linux boot
aop investigate linux boot --recent-minutes 30 --format json
```

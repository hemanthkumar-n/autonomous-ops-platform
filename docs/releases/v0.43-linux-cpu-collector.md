# AOP v0.43 Work Note - Linux CPU Collector

Status: first slice implemented; v0.43 is not yet a complete release.

## What changed

The bounded investigation loop can now register `build_linux_cpu_collector`.
It calls the existing read-only Linux CPU workflow with incident persistence
disabled, then adds observed load, task states, vmstat CPU time, PSI pressure,
and CPU findings as attributed `EvidenceItem` records.

The collector links a finding to a hypothesis only when its primary diagnosis
matches an evidence ID explicitly required by that hypothesis. A diagnosis
below 80% source confidence keeps the blocking gap. Evidence from a host other
than the requested host is rejected and audited as a collector error. The loop
can produce an RCA candidate, while `root_cause` remains unconfirmed.

## Example

Given a CPU contention hypothesis requiring
`linux.cpu.finding.cpu_saturation`, an observed `cpu_saturation` finding can
support it. If the workflow instead finds `io_pressure_behind_load`, AOP
records that finding and leaves the CPU contention hypothesis unsupported.
Missing CPU evidence or a host mismatch cannot clear the original gap.

## Current limits

This collector runs on the local Linux host. AOP does not yet provide remote
host execution or Kubernetes node routing for this workflow. The CPU workflow
currently distinguishes CPU saturation, D-state blocked tasks, I/O pressure,
and steal time. It does not yet collect cgroup CPU throttling counters. The
collector must be explicitly registered by its caller; the demo fixture still
uses a synthetic memory collector.

# v0.42.0: Source-Class Prompt Budgets And Agent Adoption

Date: 2026-10-09

## Why This Release Exists

v0.41 created one retrieval interface, but two reasoning agents still used the
older hybrid incident-memory API. A globally ranked result list could also let
many similar runbooks consume the complete prompt allowance before historical
or semantic context was considered.

v0.42 makes the unified path operational across all three Kubernetes reasoning
agents and adds deterministic source-class allocation.

## Prompt Allocation

The default four-item prompt allowance is:

| Knowledge class | Reserved items | Included sources |
|---|---:|---|
| Trusted guidance | 2 | Internal runbooks and source-reviewed guidance |
| Historical context | 1 | Exact incident memory and recurrence patterns |
| Semantic similarity | 1 | Optional vector similarity results |

If a class has no available match, AOP fills the unused slot with the
highest-ranked remaining result. This preserves useful context without letting
one noisy class hide another class that is available.

## Diagnostics

`aop knowledge search` now reports:

```text
prompt_class_budgets
prompt_selected_counts
prompt_estimated_tokens
```

JSON output includes the complete typed `prompt_selection` object with
available and selected class counts. The token number uses AOP's deterministic
provider-neutral estimate. It is a context-planning guardrail, not an API bill
or an exact model tokenizer result.

## Agent Adoption

These reasoning paths now call one shared adapter:

```text
Kubernetes incident + deterministic classification
  -> KnowledgeQuery
  -> unified retrieval
  -> source-class prompt allocation
  -> bounded attributed context
  -> RCA / incident analysis / remediation guidance
```

The default agent path remains deterministic and offline. Semantic retrieval
is available explicitly but is not invoked silently for every incident.

## Safety Boundary

This remains an advisory retrieval and reasoning layer. It does not SSH,
restart kubelet or containerd, drain nodes, delete files or images, change
sysctls, or mutate Kubernetes resources.

# v0.39.0: k8s.af External Knowledge Import

Date: 2026-08-14

## Why

k8s.af is a useful index of real public Kubernetes failure stories. AOP should
learn which technologies and impacts appeared together, while preserving the
difference between historical metadata and verified operational guidance.

## What Changed

- Added an external incident metadata schema with provenance fields.
- Added a structured parser for the k8s.af index.
- Imported 59 story titles, canonical URLs, technology tags, impacts, and
  publication years.
- Added stable IDs, source checksums, and URL deduplication.
- Added search by symptom text and technology.
- Added a package-data rule so the snapshot ships with AOP.

## Commands

```bash
aop runbooks sources
aop runbooks stories search --technology CoreDNS --text "DNS OOM outage"
aop runbooks stories search --technology conntrack --text "latency errors"
aop runbooks import k8s-af
aop runbooks import k8s-af --input-file saved-k8s-af.html
```

The default live import writes a local refresh to:

```text
data/runbooks/external/k8s_af.json
```

That local refresh is ignored by Git. The reviewed release snapshot is stored
under `app/memory/runbooks/sources/`.

## Important Boundary

The import contains metadata and links only. It does not copy linked article
bodies, conference transcripts, or videos.

Every story starts with:

```text
content_scope: metadata_only
license_status: unverified
review_state: source_review_required
```

The records can support discovery and historical pattern research. They cannot
be presented as verified root causes, solutions, or remediation until the
original source is reviewed and the reusable guidance is validated.

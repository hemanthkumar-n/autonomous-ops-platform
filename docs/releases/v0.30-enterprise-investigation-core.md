# v0.30.0: Enterprise Investigation Core

Date: 2026-08-14

## Why This Release Exists

AOP has strong domain investigators now: Linux memory, CPU, disk, network,
boot, host correlation, Kubernetes node planning, and runtime planning.

Enterprise-grade agents need one common reasoning shape above those domains.
They must not jump from evidence to action. They need to track:

- what is affected
- what evidence exists
- what evidence is missing
- which hypotheses are supported
- which hypotheses are contradicted
- whether RCA is allowed yet
- why and why-not
- what audit events happened
- what should be checked next

v0.30 ports the investigation-core branch into current main as that foundation.

## Why This Matters

This is how AOP starts moving from useful tools to enterprise agents:

```text
domain investigator
  -> canonical case
  -> evidence gaps
  -> hypotheses
  -> deterministic confidence
  -> RCA candidate or collect-more-evidence
  -> audit trail
  -> human-approved next step
```

The case model can become the shared contract for:

- CLI reports
- future UI
- memory
- ChatGPT/Codex handoff
- Slack/Teams approval workflows
- enterprise audit requirements
- live server trial guardrails

## Current Adapter

The first adapter converts Linux memory investigations into canonical cases.

It preserves:

- host and optional process resource
- MemAvailable evidence
- swap evidence
- kernel OOM evidence
- cgroup memory evidence
- deterministic findings
- evidence gaps
- source confidence
- recommendations

## Safety Boundary

This release does not collect new evidence by itself and does not remediate.

It only evaluates already-collected evidence and decides whether the case is:

- ready as an RCA candidate
- blocked by evidence gaps
- requiring more evidence
- weak enough to escalate

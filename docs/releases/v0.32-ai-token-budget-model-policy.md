# v0.32.0: AI Token Budget And Model Tier Policy

## Purpose

v0.32.0 gives AOP a practical answer to token control before adding more live
providers. The goal is not to send every log line to an expensive model. The
goal is to estimate evidence size, choose an appropriate reasoning tier, and
make that decision visible to operators and future agents.

## What Changed

- Added deterministic token estimation in `app/llm/token_budget.py`.
- Added model-tier selection in `app/llm/model_policy.py`.
- Added `aop ai budget` for zero-cost token and model-tier planning.
- Added configurable model-role names:
  - `AI_LIGHT_MODEL_NAME`
  - `AI_STANDARD_MODEL_NAME`
  - `AI_DEEP_MODEL_NAME`
- Added configurable input-token budgets:
  - `AI_LIGHT_INPUT_TOKEN_BUDGET`
  - `AI_STANDARD_INPUT_TOKEN_BUDGET`
  - `AI_DEEP_INPUT_TOKEN_BUDGET`
- Added tests for budget boundaries, routing decisions, and CLI output.

## Current Model Tier Intent

```text
classification / summary
  -> light tier
  -> default model role: gpt-5-nano

normal RCA
  -> standard tier
  -> default model role: gpt-5-mini

large or complex RCA
  -> deep tier
  -> default model role: gpt-5.1

remediation planning
  -> local/default tier
  -> default provider: configured local AOP provider
```

## Demo

```bash
aop ai budget --task classification --text "pod CrashLoopBackOff after config change"
aop ai budget --task normal_rca --text "journalctl shows kubelet image pull timeout"
aop ai budget --task remediation --text "restart kubelet requested" --format json
```

This does not call an LLM or consume API tokens. It estimates and explains the
route AOP would prefer.

## Boundary

This release does not add live OpenAI API calls, API-key setup, provider
fallback execution, cost dashboards, or production model governance. It creates
the deterministic planning layer those features should use later.

## Why This Matters

Enterprise troubleshooting must be evidence-first and cost-aware:

```text
raw evidence
  -> parse and compress locally
  -> estimate token load
  -> choose model tier
  -> retrieve only relevant memory/runbooks
  -> reason with bounded context
```

This keeps AOP useful on real servers, where logs and command output can become
huge quickly.
